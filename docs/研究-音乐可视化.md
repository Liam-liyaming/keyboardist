# 调研：音乐的可视化表达

> 接上一份《打字光效与音乐质量》。这份专攻「把一首 1–2 分钟的曲子画出来」：
> 参考了音乐游戏、音乐工具/VJ 软件、声音艺术与感知研究，最后落到一个能跑的原型。

---

## 一、先看三类翻车

调研里被反复点名的失败模式，正好是我们最容易踩的：

1. **满屏频谱条 / 波形墙** —— 观众读到的是闪烁的包络，没有结构；能量永远堆在低频，画面"左边一直在抖"。
2. **示波器式"信号即图形"** —— 李萨如图只有频率比为有理数时才闭合稳定，真实音乐是一团乱线；而且要求毫秒级同步，稍有延迟就退化成噪声。
3. **彩虹 colormap + 全屏高亮** —— jet/rainbow 非感知均匀，会伪造数据边界；大面积高亮在暗环境刺眼，>3 次/秒的大面积闪烁还有光敏性癫痫风险（WCAG 2.3.1）。

## 二、音乐游戏：把时间变成距离

一切节奏游戏都在回答同一个问题：**"还有多久？"**

| 类型 | 代表 | 时间编码 |
|---|---|---|
| 透视纵深 | Guitar Hero、Beat Saber | 音符从远处飞来，距离 = 剩余时间 |
| 轴线扫描 | Lumines、NecroDancer | 线/脉动扫过，位置 = 当前拍 |
| 几何轨迹 | ADOFAI、Thumper | 节奏型画成路径弯曲与节点间距 |

### 八条可迁移原则

1. **时间必须变成距离**【共识】—— GH 的音符高速公路、Lumines 的扫描线都在做这件事。
2. **预备窗口是首要难度参数，不是音符密度**【共识】—— Beat Saber 的 note jump speed、GH 的滚动速度都交给玩家调。
3. **一色一义**【共识】—— JSAB 的"避开粉色"、Beat Saber 的红蓝，颜色只承担一个维度。
4. **正反馈 = 音乐层叠加**【共识】—— Rez 每击加一层音轨，视觉亮度跟着声部走。
5. **惩罚用缺失而非噪音**【共识】—— GH 的 miss 让音轨静音，比红闪更疼。
6. **视觉事件必须落在听觉重音上**【共识】—— 《节奏天国》制作中反复纠正机械打点。
7. **反馈要有强度曲线与留白**【共识】—— Thumper 刻意不用高级粒子；Lumines 只在大消除时给全屏特效。
8. **分层 = 重要性分层**【观察】—— 前景判定、中景音符、背景氛围靠亮度/模糊/透明度三级区分。

### 给"极简光带"的配方

- 位置 = 剩余时间：用"由暗到亮的逼近" + 固定命中线
- 亮度 = 力度，层数 = 声部
- 脉冲而非爆炸：命中给 80–120ms 亮度脉冲，仅强拍放大
- 失误 = 暗掉，不是红闪

## 三、音乐工具与 VJ：四种视觉隐喻

| 隐喻 | 代表 | 映射方式 |
|---|---|---|
| 结构 | Ableton Session、Logic 钢琴卷帘 | 音高/时间 → 二维坐标，力度 → 颜色或厚度 |
| 能量 | MilkDrop/projectM | bass/mid/treble 变量驱动方程 |
| 频段 | 频谱分析器、FabFilter Pro-Q | FFT → 空间，快攻慢放 |
| 时间 | 示波器、瀑布图 | 显示"刚刚发生"的声音 |

### 六种可视化方案与成本

| # | 方案 | 擅长 | 实现 | 60fps 成本 |
|---|---|---|---|---|
| 1 | 波形 + 段落标注 | 结构、情绪走向 | Canvas2D | ≈0 |
| 2 | 频谱瀑布/地形 | 频段、音色 | WebGL 纹理滚动 | 低 |
| 3 | 频段粒子/流体 | 能量、氛围 | WebGL FBO 反馈 | 中 |
| 4 | 钢琴卷帘/pattern | 节奏、结构 | Canvas2D | 低 |
| 5 | 程序化场景 | 情绪、抽象叙事 | Metal/WebGL | 高 |
| 6 | 极简节拍几何 | 节奏、常驻 | CoreGraphics | 极低 |

### 四条共性工程规律

1. **先降维**：没人直接画 1024 bins，通常聚成 4–8 段或几个标量。
2. **快攻慢放**：视觉包络 attack 快、release 慢，否则画面抖。
3. **分层**：结构层接低频事件（段落、小节），能量层接高频细节（瞬态）。
4. **帧率无关**：用音频时钟驱动，掉帧也不会跑调。

## 四、视听映射：哪些有实证，哪些是任意的

| 映射 | 强度 | 证据 |
|---|---|---|
| 音高 → 垂直高度 | **强** | 4 月龄婴儿已出现（Walker 2010）；跨语言有差异（波斯语用"细/厚"） |
| 响度 → 大小 | **较强** | 幅度类映射最稳（PLOS ONE 2023 因子分析） |
| 音色 → 锐度/质感 | 中 | 25 种语言、917 人、72% 一致（Čwiek et al.） |
| 节奏 → 运动速度 | 中 | 视听速度判断双向耦合 |
| 音高 → 亮度 | 弱—中 | 显著但效应小于位置 |
| **音色 → 颜色** | **任意** | 无稳定跨被试一致性，属文化/个人习得 |

**结论**：能跨文化复用的只有幅度类（高/低、大/小、快/慢）；**颜色不要承担编码**，只承担情绪与品牌。需要定量时用位置、长度、明度。

### 夜间与低打扰

- 晚间发光屏幕会抑制褪黑素、推迟昼夜节律（Chang 2015, PNAS）→ 优先低色温（琥珀），蓝青只做小面积点缀。
- 运动用呼吸式缓变（周期 8–20s），避免节拍脉冲。
- 声音轻时画面应"安静下去"，**留白即降噪**。

## 五、我们选了哪三个方案

结合「每日之歌」的场景（一个人、晚上、听 90 秒），选了三层递进：

| 模式 | 隐喻 | 映射 | 为什么选它 |
|---|---|---|---|
| **1 光河** | 键盘地平线 + 击键成光 | 音高 → 高度（对数）；力度 → 光斑尺寸；和声 → 底部光池 | 直接呼应「打字」这件事；音高→高度是强映射 |
| **2 声谱** | 瀑布/钢琴卷帘 | 时间 → 横轴、音高 → 纵轴、力度 → 亮度 | 唯一能"读懂结构"的模式，适合想看细节的人 |
| **3 呼吸** | 低频大形变 | 和声进行 → 缓慢起伏 | 夜间低打扰，不闪、不抢注意力 |

三条都遵守：颜色只分冷暖（不编码数据）、快攻慢放、音频时钟驱动、无全屏闪烁。

## 六、原型与验证

`composer/out/visualizer.html`（配 `visualizer.js`、`notes.js`、`swift-ambient-v3.m4a`）：
用今天真实生成的 186 个音符事件驱动，空格播放/暂停，按 1/2/3 切换模式。

**验证方法**：headless Chrome 抓不到 canvas 合成结果，所以改成把 `canvas.toDataURL()`
写进 DOM，再用 `--dump-dom` 取回来解码成 PNG。这样每一帧都能被静态检查，
不用盯着屏幕盲调。

## 七、下一步：移植进 App

现在只是浏览器原型。要变成产品，需要：

1. **Swift 演出窗口**：`NSWindow` + CoreGraphics（模式 1/3 成本极低），或 Metal（模式 2 流畅度更好）
2. **与音频时钟对齐**：现在播放用的是 `afplay`/`NSSound`，需要换成 `AVAudioEngine` 才能拿到精确播放位置
3. **夜间模式**：22 点后自动切到「呼吸」，降低色温
4. **分享出口**：录制 10 秒循环 + 封面卡，导出 GIF/MP4
